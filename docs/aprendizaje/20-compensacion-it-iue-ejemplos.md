# 💸 Compensación IT-IUE: 3 Ejemplos Numéricos Completos (Art. 77 Ley 843)

**Módulo:** 5 — Impuestos Bolivianos  
**Tiempo de lectura:** 12 minutos  
**Nivel:** Intermedio

---

## 📜 La norma en una línea

> **Art. 77, Ley 843:** El Impuesto a las Transacciones (IT) pagado durante el ejercicio se **compensa** contra el Impuesto sobre las Utilidades de las Empresas (IUE) determinado al cierre de gestión. **El exceso de IT que no pueda compensarse SE PIERDE**: no se devuelve, no se arrastra, no se acredita.

Esta guía muestra los **tres escenarios posibles** con montos realistas en bolivianos, para que entiendas exactamente qué pasa con tu dinero en cada caso.

---

## 🧠 Repaso rápido (30 segundos)

| Impuesto | Base | Tasa | Frecuencia |
|----------|------|:----:|------------|
| **IT** | Ingresos **brutos** de cada venta | 3% | Mensual (Form. 400) |
| **IUE** | Utilidad imponible del año | 25% | Anual (Form. 500) |

**La compensación ocurre una vez al año**, al presentar el Form. 500:

```text
IUE a pagar = IUE determinado − IT acumulado pagado en el año
              (si el resultado es negativo, se paga Bs 0
               y el sobrante de IT se PIERDE)
```

# 🟢 ESCENARIO 1: IT menor que IUE → pagas la diferencia

### La empresa

**Comercializadora Andina SRL** — distribuidora de tecnología con buenos márgenes. Gestión 2026.

### Paso 1: IT pagado mes a mes (3% sobre ingresos brutos)

| Mes | Ingresos brutos | IT (3%) |
|-----|----------------:|--------:|
| Enero | Bs 150.000 | Bs 4.500 |
| Febrero | Bs 140.000 | Bs 4.200 |
| Marzo | Bs 180.000 | Bs 5.400 |
| Abril | Bs 160.000 | Bs 4.800 |
| Mayo | Bs 170.000 | Bs 5.100 |
| Junio | Bs 190.000 | Bs 5.700 |
| Julio | Bs 165.000 | Bs 4.950 |
| Agosto | Bs 175.000 | Bs 5.250 |
| Septiembre | Bs 185.000 | Bs 5.550 |
| Octubre | Bs 195.000 | Bs 5.850 |
| Noviembre | Bs 200.000 | Bs 6.000 |
| Diciembre | Bs 210.000 | Bs 6.300 |
| **TOTAL** | **Bs 2.120.000** | **Bs 63.600** |

### Paso 2: IUE determinado al cierre

```text
Utilidad imponible 2026:        Bs 400.000
IUE determinado (25%):          Bs 100.000
```

### Paso 3: Compensación (Art. 77)

```text
IUE determinado:                Bs 100.000
(−) IT acumulado pagado:      ( Bs  63.600 )
─────────────────────────────────────────
IUE A PAGAR (Form. 500):        Bs  36.400   ✅ Pagas la diferencia
```

### Lectura del escenario

La empresa fue rentable: su IUE (Bs 100.000) superó con creces el IT que ya venía pagando mes a mes. El IT funcionó como un **pago a cuenta** del impuesto anual.

```text
┌─────────────────────────────────────────────────────────┐
│  🟢 IT (63.600) < IUE (100.000)                          │
│  → Pagas Bs 36.400 en el Form. 500                       │
│  → No se pierde nada: todo el IT se compensó             │
└─────────────────────────────────────────────────────────┘
```

# 🟡 ESCENARIO 2: IT igual a IUE → no pagas nada

### La empresa

**Servicios Logísticos del Beni SA** — márgenes moderados. Gestión 2026.

### Paso 1: IT acumulado del año

```text
Ingresos brutos anuales:        Bs 2.000.000
IT acumulado (3%):              Bs   60.000
(pagado en 12 declaraciones mensuales del Form. 400)
```

### Paso 2: IUE determinado al cierre

```text
Utilidad imponible 2026:        Bs 240.000
IUE determinado (25%):          Bs  60.000
```

### Paso 3: Compensación (Art. 77)

```text
IUE determinado:                Bs 60.000
(−) IT acumulado pagado:      ( Bs 60.000 )
─────────────────────────────────────────
IUE A PAGAR (Form. 500):        Bs      0    ✅ No pagas nada
Exceso perdido:                 Bs      0    ✅ No se pierde nada
```

### Lectura del escenario

Es el **punto de equilibrio tributario**: el IT que pagaste durante el año cubrió exactamente tu IUE anual. Matemáticamente ocurre cuando:

```text
Ingresos × 3%  =  Utilidad × 25%
es decir, cuando la utilidad es 12% de los ingresos
(3 ÷ 25 = 0,12)
```

> 💡 **Dato útil:** si tu margen de utilidad imponible es **exactamente 12%**, tu IT y tu IUE se anulan. Por debajo de 12% entras al escenario 3 (el peligroso).

```text
┌─────────────────────────────────────────────────────────┐
│  🟡 IT (60.000) = IUE (60.000)                           │
│  → Pagas Bs 0 en el Form. 500                            │
│  → Compensación perfecta, sin pérdida                    │
└─────────────────────────────────────────────────────────┘
```

# 🔴 ESCENARIO 3: IT mayor que IUE → el exceso SE PIERDE

### La empresa

**Supermercados Mamoré SRL** — retail de alto volumen y márgenes muy bajos (típico de supermercados). Gestión 2026.

### Paso 1: IT acumulado del año

```text
Ingresos brutos anuales:        Bs 5.000.000
IT acumulado (3%):              Bs  150.000
(pagado mes a mes, aunque la empresa casi no tenga utilidad)
```

### Paso 2: IUE determinado al cierre

```text
Utilidad imponible 2026:        Bs 200.000   (margen de solo 4%)
IUE determinado (25%):          Bs   50.000
```

### Paso 3: Compensación (Art. 77)

```text
IUE determinado:                Bs  50.000
(−) IT acumulado pagado:      ( Bs 150.000 )
─────────────────────────────────────────
Resultado:                    ( Bs 100.000 )  ← negativo

IUE A PAGAR (Form. 500):        Bs       0
EXCEDENTE DE IT PERDIDO:        Bs 100.000    ⚠️ SE PIERDE PARA SIEMPRE
```

### ⚠️ ADVERTENCIA CRÍTICA

```text
┌─────────────────────────────────────────────────────────────┐
│  🔴 IT (150.000) > IUE (50.000)                              │
│  → Pagas Bs 0 de IUE, PERO...                                │
│  → Bs 100.000 de IT se PERDIERON definitivamente            │
│                                                              │
│  ❌ NO se devuelven al contribuyente                          │
│  ❌ NO se arrastran a la gestión 2027                         │
│  ❌ NO se acreditan contra otros impuestos                    │
│  ❌ NO se pueden reclamar                                     │
│                                                              │
│  💸 Es dinero que salió de tu caja y nunca volverá.          │
└─────────────────────────────────────────────────────────────┘
```

### Lectura del escenario

Este es el caso de los **negocios de alto volumen y margen bajo**: supermercados, farmacias, estaciones de servicio, retail. Facturan millones (pagan mucho IT) pero su utilidad es pequeña (pagan poco IUE). El Art. 77 los castiga silenciosamente cada año.

**Por eso un buen ERP debe alertar:** si al mes de octubre el IT acumulado ya supera la proyección de IUE anual, el contador debe saber que el exceso de los meses restantes **se va a perder**.

## 📊 Comparativa de los 3 escenarios

| | 🟢 Escenario 1 | 🟡 Escenario 2 | 🔴 Escenario 3 |
|---|---:|---:|---:|
| Ingresos brutos | Bs 2.120.000 | Bs 2.000.000 | Bs 5.000.000 |
| IT acumulado (3%) | Bs 63.600 | Bs 60.000 | Bs 150.000 |
| Utilidad imponible | Bs 400.000 | Bs 240.000 | Bs 200.000 |
| Margen de utilidad | 18,9% | 12,0% | 4,0% |
| IUE determinado (25%) | Bs 100.000 | Bs 60.000 | Bs 50.000 |
| **IUE a pagar (Form. 500)** | **Bs 36.400** | **Bs 0** | **Bs 0** |
| **IT perdido** | **Bs 0** | **Bs 0** | **Bs 100.000** ⚠️ |
| Carga tributaria total | Bs 100.000 | Bs 60.000 | Bs 150.000 |

> 🔍 **Observación final clave:** en el Escenario 3, la empresa con **menor utilidad** (Bs 200.000) terminó pagando **más impuestos en total** (Bs 150.000) que la empresa del Escenario 1 que ganó el doble (Bs 400.000 de utilidad, Bs 100.000 de impuestos). Así de distorsivo puede ser el IT en negocios de margen bajo.

## 💻 Cómo lo implementa el ERP

```javascript
// Compensación IT-IUE según Art. 77 Ley 843
function compensarITcontraIUE(iueDeterminado, itAcumuladoPagado) {
  const iuePorPagar = iueDeterminado - itAcumuladoPagado;

  if (iuePorPagar > 0) {
    // 🟢 Escenario 1: el IT no alcanza, pagas la diferencia
    return {
      escenario: 'IT_MENOR_QUE_IUE',
      iuePorPagar: redondear2(iuePorPagar),
      itCompensado: itAcumuladoPagado,
      excesoPerdido: 0,
      mensaje: 'Pagas la diferencia en el Form. 500'
    };
  }

  if (iuePorPagar === 0) {
    // 🟡 Escenario 2: compensación perfecta
    return {
      escenario: 'IT_IGUAL_A_IUE',
      iuePorPagar: 0,
      itCompensado: itAcumuladoPagado,
      excesoPerdido: 0,
      mensaje: 'Compensación exacta: no pagas IUE'
    };
  }

  // 🔴 Escenario 3: el IT supera al IUE → el exceso SE PIERDE
  return {
    escenario: 'IT_MAYOR_QUE_IUE',
    iuePorPagar: 0,
    itCompensado: iueDeterminado,
    excesoPerdido: redondear2(Math.abs(iuePorPagar)),
    mensaje: '⚠️ EXCESO DE IT PERDIDO: no se devuelve ni se arrastra'
  };
}

// Pruebas con los 3 escenarios de esta guía:
compensarITcontraIUE(100000, 63600);
// → { escenario: 'IT_MENOR_QUE_IUE', iuePorPagar: 36400, excesoPerdido: 0 }

compensarITcontraIUE(60000, 60000);
// → { escenario: 'IT_IGUAL_A_IUE', iuePorPagar: 0, excesoPerdido: 0 }

compensarITcontraIUE(50000, 150000);
// → { escenario: 'IT_MAYOR_QUE_IUE', iuePorPagar: 0, excesoPerdido: 100000 }
```

---

## 🎯 Consejos prácticos para el contador

1. **Proyecta en octubre:** compara el IT acumulado contra el IUE proyectado. Si el IT ya lo supera, todo lo que pagues en noviembre y diciembre **se perderá**.

2. **Identifica tu margen crítico:** si tu utilidad imponible es menor al **12% de tus ingresos**, estás en zona de pérdida de IT.

3. **No confundas con saldos a favor de IVA:** el IVA con saldo a favor **sí** se arrastra al mes siguiente. El IT excedente **no**. Son reglas distintas.

4. **Registra el exceso perdido como gasto no deducible** en tus papeles de trabajo: es una pérdida real que debe explicarse en la conciliación contable-tributaria.

## 📚 Resumen

| Escenario | Condición | IUE a pagar | Exceso de IT |
|-----------|-----------|:-----------:|:------------:|
| 🟢 1 | IT < IUE | Diferencia | No hay |
| 🟡 2 | IT = IUE | Bs 0 | No hay |
| 🔴 3 | IT > IUE | Bs 0 | **SE PIERDE** |

**Norma:** Art. 77, Ley 843 (Texto Ordenado vigente).

---

## 🎓 Lo que aprendiste

1. La compensación IT-IUE ocurre **una vez al año**, al presentar el Form. 500.
2. Si tu margen de utilidad es **mayor a 12%** de tus ingresos, el IT se compensa completo (escenarios 1 y 2).
3. Si tu margen es **menor a 12%**, parte del IT **se pierde para siempre** (escenario 3).
4. Los negocios de **alto volumen y margen bajo** son los más castigados por esta regla.
5. Un ERP bien diseñado **alerta del exceso proyectado** antes de que sea demasiado tarde.
